# Day 22 Learning: 案件初日準備・受入情報整理

## 学習開始前に実行するスクリプト

Day 22は案件初日の準備と情報整理を行うため、AWSラボ環境は使用しない。

```text
All_Setup.sh: 不要
Ansible: 不要
CloudTrail一時Trail: 不要
S3 Data Event: 不要
```

AWSリソースを作成せず、既存資料、初日用メモ、確認事項の整理に集中する。

## 1. 今日の目的

2026年7月2日の案件初日に、現場ルール、AWS環境、作業体制、最初の依頼を落ち着いて確認し、安全に作業へ着手できる状態を作る。

```text
参画前に準備する
  -> 初日の案内と持ち物を確認する
  -> 自己紹介と質問を準備する
  -> 公開情報と非公開情報を分ける

初日に情報を受け取る
  -> 端末・Account・Tool・資料・連絡先を確認する
  -> 作業ルールと承認フローを確認する
  -> AWS環境と責任分界を確認する

最初の作業依頼を受ける
  -> 対象・目的・期限・承認範囲を確認する
  -> 不明点を要確認事項として整理する
  -> 着手前に認識を共有する
```

Day 22ではAWS設定変更を行わない。

初日にすべてを理解しようとせず、次の3点を優先する。

1. 誤操作・情報持ち出しを防ぐための現場ルール
2. 最初の作業を進めるために必要な情報
3. 困ったときの確認先と報告経路

## 4. 公開リポジトリへ記載しない情報

このリポジトリはGitHubで共有・公開される可能性がある。案件初日の案内や現場で受領した情報を、そのまま記載しない。

## 記載しない情報の例

- 集合場所の詳細
- 担当者氏名
- 内線番号、電話番号、メールアドレス
- 顧客名、銀行名、案件コード
- AWS Account ID、Role ARN、User名
- VPC ID、Subnet ID、Security Group ID
- 社内URL、VDI接続先、Bridge Server情報
- 手順書、設計書、構成図の実データ
- Access Key、Secret、Token、Password
- 実際のBucket名、Host名、IPアドレス
- Teams Group名、Channel名
- 障害・Finding・脆弱性の実情報

## 記録場所の分離

| 情報 | 記録先 |
|---|---|
| 一般化した学習内容 | 本リポジトリ |
| 個人ラボの設定 | 本リポジトリ。ただし秘密情報は除外 |
| 初日の集合案内 | 会社メール、個人の安全な予定管理 |
| 現場固有の手順・設定 | 現場指定の保存先 |
| 作業証跡 | 現場指定の証跡保存先 |
| Credential | 現場指定の認証基盤・Secret管理 |

現場情報を学習へ反映する場合は、固有名詞、識別子、値、構成を一般化する。

```text
実案件:
prod-resona-transfer-archive-001

学習用:
example-bucket
```

## 15. AWS CLI利用方法を確認する

現場でAWS CLIが使える場合でも、個人ラボと同じ実行方法とは限らない。

確認すること:

- AWS CLIのVersion
- Credential取得方法
- Profile命名規則
- Role切替方法
- Proxy設定
- Default Region
- `--no-cli-pager`利用可否
- JSON、Table、Textの出力ルール
- Command実行ログの保存方法
- 変更Commandの承認・実行方法
- 共通Shell経由で実行する必要があるか
- Direct CLI実行が禁止されていないか

現場で最初に確認するRead-only Command候補:

```text

```

実行前に確認する。

```text
- 指定Profile・Roleは何か
- 出力をどこへ保存するか
- Account IDを画面・CLIの両方で確認するか
```

本ドキュメントへ現場のProfile名、Account ID、Role ARNを追記しない。

## 16. 既存Shell・Toolの受入確認

7月案件で、別案件で観察した共通関数Shell、conf、JP1が使われるとは限らない。

存在する場合だけ、次を確認する。

| 確認対象 | 確認内容 |
|---|---|
| 実行Shell | Entry point、引数、実行User |
| 共通関数 | `source`先、関数一覧、戻り値 |
| conf | Account、Region、Resource、Log設定 |
| AWS Command | Direct実行かWrapper経由か |
| Error処理 | Return code、Exit code、Message |
| Log | 出力先、Mask、保存期間 |
| Multi-account | Account切替、誤操作防止 |

## 29. 不明点への対応

## 良い対応

```text
1. 資料と既存手順を確認する

3. 作業への影響を整理する

```

## 避ける対応

```text

  -> 推測で変更する

エラーが出た
  -> 別Commandを次々試す

資料がない
  -> 個人端末へ情報を持ち出して調べる

回答待ち
  -> 状況を共有せず止まる
```

回答待ちの間は、変更を伴わない資料確認、手順整理、質問整理などを進める。

## 30. 現場情報をこの学習へ反映する場合

現場で学んだ一般的な考え方は、機密情報を除いて学習へ反映できる。

反映してよい例:

- 手順書レビューで一般的に確認する観点

- 変更前後・切り戻し・証跡の一般的な流れ
- Shell関数、Return code、Logの一般的な読解方法

反映しない例:

- 実案件のShell Script
- 実際のBucket Policy
- 顧客・案件固有の構成
- Account・Resource・User情報
- 実際のFinding・脆弱性・障害
- 内部資料の文章やScreenshot

一般化する場合も、会社・顧客のルールを優先する。
