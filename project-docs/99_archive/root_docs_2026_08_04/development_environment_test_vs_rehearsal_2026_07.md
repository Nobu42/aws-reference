# 開発環境設定テストとテストリハの違い

作成日: 2026-07-17

この資料は、AWSセキュリティ監査指摘対応における「開発環境設定テスト」と「テストリハ」の違いを整理するためのメモである。

## 結論

| 項目 | 開発環境設定テスト | テストリハ |
| :--- | :--- | :--- |
| 主な目的 | 設定が正しく動くことを確認する | 本番作業の流れを事前に確認する |
| 主な環境 | 開発環境 | 本番作業前の確認環境、または本番環境の変更直前まで |
| 実施内容 | Metric Filter、Alarm、通知、証跡取得などを実際に確認する | 作業手順、確認手順、戻し手順、連絡、証跡取得の流れを確認する |
| 本番設定変更 | 行わない | 原則行わない |
| 成果物 | 設定テスト結果、通知確認結果、証跡 | リハーサル結果、手順修正点、当日作業の確認事項 |
| 観点 | 技術的に正しく動くか | 本番当日に迷わず安全に進められるか |

## 開発環境設定テスト

開発環境設定テストは、開発環境で実際に設定を行い、想定どおりに検知、通知、証跡取得ができることを確認する作業である。

今回のWBSでは、2026-07-24に先行作業として要件番号4.5と4.7の開発環境設定テストを行う。

- REQ-4.5: CloudTrail設定変更監視
- REQ-4.7: KMSキー無効化・削除予約監視

確認観点は以下である。

- Metric Filterを作成できること
- CloudWatch Alarmを作成できること
- 対象イベントを検知できること
- 通知先へ通知されること
- 変更前後の証跡を取得できること
- 手順書どおりに作業できること
- 戻し手順が成立すること

## テストリハ

テストリハは、本番作業前に作業全体の流れを確認する予行演習である。

設定が動くかどうかだけではなく、本番当日に必要な連絡、役割分担、確認、証跡取得、切り戻し判断まで含めて確認する。

確認観点は以下である。

- 作業開始連絡の流れ
- 作業者、確認者、承認者の役割
- 対象アカウント、対象リージョン、対象リソースの確認
- 作業手順の読み合わせ
- 変更前証跡の取得タイミング
- 設定作業の順序
- 変更後確認の方法
- 通知確認の方法
- 異常時の判断基準
- 切り戻し手順
- 作業完了報告の流れ

本番環境でテストリハを行う場合でも、原則として本番設定変更は行わない。
本番環境を使う場合は、対象画面や対象リソースの確認、変更直前までの手順確認、証跡取得方法の確認にとどめる。

## 今回のスケジュール上の整理

| 時期 | 作業 | 位置づけ |
| :--- | :--- | :--- |
| 2026-07-24 | 先行作業 REQ-4.5 / REQ-4.7 の開発環境設定テスト | 先行分の設定が開発環境で正しく動くか確認する |
| 2026-08中 | 残り4番台の開発環境設定テスト | 先行分以外の対応必要要件を開発環境で確認する |
| 2026-08-31週 | テストリハ | 本番作業前に手順、確認、戻し、証跡取得の流れを確認する |
| 2026-09-12 | 本番リリース | 承認後、本番環境へ設定を反映する |

## WBSでの書き分け

WBS上では、以下のように書き分ける。

```text
開発環境設定テスト
= 開発環境で設定を行い、検知、Alarm、通知、証跡取得を確認する作業

テストリハ
= 本番作業前に、作業手順、確認手順、戻し手順、証跡取得手順の流れを確認する作業
```

誤解を避けるため、テストリハの備考には以下を明記する。

```text
本番設定変更はリリース当日に実施する。
テストリハでは、本番作業の流れ、対象確認、証跡取得方法、切り戻し判断を確認する。
```
